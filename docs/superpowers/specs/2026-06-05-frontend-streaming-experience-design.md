# Frontend Streaming Experience Design

> 日期：2026-06-05 | 状态：待评审 | 版本：v1

## 一、背景

当前项目已经完成 Go API + Vue SPA 的基础切换，但前端在核心创作链路上仍存在明显缺口：

1. 作品详情页只能显示基础章节列表，无法作为真正的创作总控页使用。
2. 章节虽然已有后端详情接口，但前端没有章节阅读页，也没有进入章节详情的交互入口。
3. SSE 已接入，但当前仅展示一行字符串消息，无法支撑实时创作体验。
4. 点击“继续生成”后，用户无法明确知道当前生成到哪一步、哪一章正在生成、应该去哪里看流式内容。

本设计文档的目标，是在现有后端架构上，把前端交互补齐到“操作完整、状态清晰、生成可见”的可用水平。

## 二、目标

本轮设计目标如下：

1. 首页书架页可直接展示作品进度与状态。
2. 作品详情页成为总控页，负责展示状态、章节、日志和控制操作。
3. 新增章节页，支持正文阅读、漫画查看、上下章导航。
4. 当章节正在生成时，章节页可实时显示流式正文。
5. SSE 从“单行提示”升级为“结构化事件协议 + 页面状态更新机制”。
6. 继续生成、停止生成、重生成形成完整前端闭环。

## 三、非目标

以下内容不纳入本轮：

1. 多标签页状态同步。
2. 高级日志筛选、搜索和导出。
3. SSE 断线后的消息补发或服务端事件回放。
4. Agent / Checkpoint 的前端深化设计。

## 四、页面与路由设计

补充边界原则：

1. 详情页不展示章节正文流式内容。
2. 详情页只负责总进度、章节导航、控制操作和事件日志。
3. 章节正文实时生成只在章节页展示。

### 1. 首页 `/`

首页继续承担作品书架角色，但每张作品卡片需要具备更明确的状态表达。

每张卡片至少显示：

1. 标题
2. 创作模式
3. 文本进度 `text_done / planned`
4. 漫画完成数 `comic_done`
5. 当前状态 `drafting / stopped / completed / failed`

每张卡片提供的操作：

1. 进入作品详情页
2. 快速继续生成
3. 快速停止生成

目标是让用户在首页就能判断某部作品是否仍在生成、是否需要继续、是否已经可阅读。

### 2. 作品详情页 `/novel/:id`

作品详情页定位为“整本书的总控页”，不承担正文细节阅读，而是承担状态观察、章节导航和任务控制职责。

页面分为四个区域：

1. 顶部信息区
2. 进度总览区
3. 章节列表区
4. 事件流面板

顶部信息区显示：

1. 标题
2. 模式
3. 总状态
4. SSE 连接状态
5. 继续生成 / 停止生成按钮

进度总览区显示：

1. 计划章节数
2. 已完成章节数
3. 已完成漫画页数
4. 当前步骤
5. 当前正在生成的章节号

章节列表区每一章显示：

1. 章节号
2. 标题
3. 当前状态
4. 更新时间
5. 可读状态
6. 重生成操作
7. 阅读入口

事件流面板为可展开区域，持续追加实时日志，例如：

1. 开始生成
2. 大纲生成中
3. 第 N 章开始生成
4. 第 N 章生成完成
5. 第 N 章漫画开始/完成
6. 失败信息

继续生成后的明确引导规则：

1. 用户点击“继续生成”成功后，详情页立即显示提示：`总进度请留在详情页查看，单章实时正文请进入当前生成章节。`
2. 一旦后端推送 `current_chapter_no`，详情页固定显示 CTA：`查看第 N 章实时正文`。
3. 当前生成中的章节在章节列表中高亮显示，并带有 `实时生成中` 标签。
4. 首页触发“快速继续生成”时，只承担快捷控制，不承担正文查看；成功后应引导进入详情页，再由详情页跳转到当前生成章节。

### 3. 章节页 `/novel/:id/chapter/:no`

章节页定位为“单章节阅读 + 单章节实时生成页”。

页面采用左右布局：

1. 左侧正文区
2. 右侧漫画区

顶部显示：

1. 作品标题
2. 当前章节号与章节标题
3. 当前章节状态
4. 返回作品详情
5. 上一章 / 下一章
6. 重生成本章

正文区显示规则：

1. 章节已完成时，显示最终正文。
2. 章节生成中时，显示流式正文面板。
3. 章节尚未开始时，显示明确空状态。

漫画区显示规则：

1. 有漫画页时显示缩略图或分页图。
2. 漫画尚未生成时显示等待状态。
3. 漫画生成中时显示进行中状态与新页追加。

章节路由与导航边界规则：

1. 只要 `current_chapter_no` 已知，就允许进入对应章节页，即使正文尚未完成。
2. 若章节号存在于计划中但正文尚未落库，章节页显示占位态，并建立 SSE 等待该章流式正文。
3. 若章节号不在计划内或作品不存在，章节页显示明确的不存在状态，不进入正文流展示。
4. 若当前是第 1 章，则“上一章”按钮禁用。
5. 若当前是计划中的最后一章且不存在下一章，则“下一章”按钮禁用。
6. 若下一章在计划中但尚未生成，允许进入占位章节页。

## 五、SSE 事件协议设计

当前 SSE 结构过于松散，前端只能将 `detail` 文本直接显示，无法驱动复杂界面。本轮需要改为结构化事件协议。

### 1. `novel_status`

用于驱动作品详情页的顶部状态卡。

示例：

```json
{
  "type": "novel_status",
  "novel_id": 12,
  "status": "drafting",
  "text_status": "writing",
  "image_status": "generating",
  "current_step": "chapter_generating",
  "message": "正在生成第 3 章"
}
```

### 2. `progress_summary`

用于驱动首页卡片与详情页进度概览。

示例：

```json
{
  "type": "progress_summary",
  "novel_id": 12,
  "planned": 10,
  "text_done": 2,
  "comic_done": 1,
  "current_chapter_no": 3
}
```

### 3. `chapter_status`

用于更新章节列表状态与章节页顶部状态。

示例：

```json
{
  "type": "chapter_status",
  "novel_id": 12,
  "chapter_no": 3,
  "status": "writing",
  "title": "雨夜追踪",
  "message": "第 3 章开始生成"
}
```

### 4. `chapter_stream`

这是章节页最关键的事件，用于正文流式追加。

示例：

```json
{
  "type": "chapter_stream",
  "novel_id": 12,
  "chapter_no": 3,
  "delta": "门外的脚步声越来越近，林澈屏住呼吸。",
  "done": false
}
```

完成事件：

```json
{
  "type": "chapter_stream",
  "novel_id": 12,
  "chapter_no": 3,
  "delta": "",
  "done": true
}
```

### 5. `outline_stream`

用于详情页展示流式大纲内容或大纲生成中的摘要信息。

示例：

```json
{
  "type": "outline_stream",
  "novel_id": 12,
  "delta": "故事从一座被遗忘的港口城开始……",
  "done": false
}
```

### 6. `comic_status`

用于章节页右侧漫画区和详情页章节状态更新。

示例：

```json
{
  "type": "comic_status",
  "novel_id": 12,
  "chapter_no": 3,
  "page_no": 1,
  "status": "done",
  "image_urls": ["/images/12/3_1.png"]
}
```

### 7. `log`

用于详情页事件流面板展示可读时间线。

示例：

```json
{
  "type": "log",
  "novel_id": 12,
  "level": "info",
  "timestamp": "2026-06-05 11:20:31",
  "message": "第 3 章已完成，已加入漫画生成队列"
}
```

### 8. `error`

错误事件必须带作用域，便于前端挂载到正确位置。

示例：

```json
{
  "type": "error",
  "scope": "chapter",
  "novel_id": 12,
  "chapter_no": 3,
  "message": "第 3 章生成失败：上游模型超时"
}
```

### 9. 事件职责矩阵

| 事件类型 | 生产时机 | 消费页面 | 更新字段 | 是否驱动 UI 状态 | 说明 |
|------|------|------|------|------|------|
| `novel_status` | 作品开始/暂停/继续/完成/失败 | 首页、详情页 | 作品状态、当前步骤 | 是 | 作品级状态真源 |
| `progress_summary` | 章节或漫画进度变化后 | 首页、详情页 | planned/text_done/comic_done/current_chapter_no | 是 | 进度汇总真源 |
| `chapter_status` | 章节排队/开始/完成/失败/重生成 | 详情页、章节页 | 单章节状态、标题 | 是 | 章节状态真源 |
| `chapter_stream` | 当前章节正文流式输出中 | 章节页 | 流式正文缓冲 | 是 | 仅章节页消费正文流 |
| `outline_stream` | 大纲流式输出中 | 详情页 | 大纲临时流内容 | 否 | 仅服务于大纲生成摘要区 |
| `comic_status` | 漫画页开始/完成/失败 | 详情页、章节页 | 漫画状态、图片列表 | 是 | 漫画状态真源 |
| `log` | 任意重要节点 | 详情页 | 日志列表 | 否 | 仅用于展示，不作为状态真源 |
| `error` | 任意失败场景 | 首页、详情页、章节页 | 错误区、日志区 | 部分 | 展示错误；必要时触发快照校准 |

事件优先级与冲突规则：

1. `log` 仅用于展示，不得驱动业务状态。
2. `progress_summary.current_chapter_no` 是“当前生成章节号”的唯一真源。
3. `chapter_status` 是单章状态的唯一真源。
4. `novel_status` 是作品总状态和当前步骤的唯一真源。
5. `error` 用于错误展示；若页面局部状态与快照冲突，应触发接口重新拉取校准。
6. `outline_stream` 只作用于大纲摘要信息，不承担正文流体验。

## 六、前端状态流转设计

前端状态分为三层：

1. 快照状态：来自普通接口，用于页面首次渲染与断线校准。
2. 实时事件状态：来自 SSE，用于局部增量更新。
3. 派生状态：由快照和实时状态组合计算得到，用于按钮、标签和视图判断。

### 1. 详情页状态流

进入页面时：

1. 请求详情接口，拿到作品、章节、大纲、漫画页和进度快照。
2. 建立 SSE 连接。
3. 连接成功后显示在线状态。

接收事件后：

1. `novel_status` 更新顶部状态卡。
2. `progress_summary` 更新进度概览。
3. `chapter_status` 精准更新章节列表中对应章节。
4. `outline_stream` 更新大纲生成中的流式区域。
5. `comic_status` 更新章节漫画状态。
6. `log` 追加到事件面板。
7. `error` 同时进入错误区域与事件面板。

点击“继续生成”后：

1. 按钮进入 loading。
2. 调用恢复接口。
3. 前端立刻进入“等待后续事件”状态。
4. 如果 2-3 秒内没有收到事件，则主动重新拉取详情接口校准。

详情页中的继续生成闭环：

1. 用户点击“继续生成”。
2. 按钮进入 loading，并暂时禁用重复点击。
3. 请求成功后，页面显示引导文案，并在事件流追加“已请求继续生成”。
4. 页面进入 `resuming` 等待态，等待首个 `novel_status` 或 `progress_summary` 到达。
5. 一旦 `current_chapter_no` 到达，显示 `查看第 N 章实时正文` CTA，并高亮章节列表对应章节。
6. 若等待超时，则自动回拉详情快照校准。
7. 若请求失败，则恢复按钮状态，并在顶部错误区显示失败原因。

### 2. 章节页状态流

进入页面时：

1. 请求章节详情接口。
2. 建立 novel 级 SSE 连接。
3. 仅消费与当前章节相关的事件。

章节页的正文显示策略：

1. 若章节已完成，则显示最终正文。
2. 若章节生成中，则显示流式正文。
3. 若数据库中已有内容，则先显示已有正文，再追加实时片段。
4. 最终完成后，以服务端最终正文重新校准。

接收事件后：

1. `chapter_status` 更新章节状态。
2. `chapter_stream` 将 `delta` 追加到流式正文缓冲区。
3. `comic_status` 为当前章节追加漫画页或更新状态。
4. `error` 显示章节级错误提示。

离开章节页时：

1. 关闭 SSE。
2. 清空当前章节流式缓冲。
3. 防止不同章节串流。

重生成闭环：

1. 用户在详情页或章节页触发“重生成本章”。
2. 按钮进入 loading，旧正文与旧漫画先保留，但标记为“旧版本结果”。
3. 章节状态进入 `writing`，并显示 `重生成中` 标签。
4. 新的 `chapter_stream` 到达后，章节页显示新的实时正文区域，旧版本区域折叠但仍可查看。
5. 新的漫画结果到达前，旧漫画保留显示，并标记“上一版本”。
6. 当新章节与新漫画完成后，用新结果替换默认展示内容。
7. 若重生成失败，则保留旧结果作为可读回退内容，同时显示失败提示并允许再次重试。

## 七、错误与空状态矩阵

### 1. 错误状态

| 场景 | 展示位置 | 页面行为 | 恢复策略 |
|------|------|------|------|
| SSE 未连接 | 顶部连接状态 | 显示未连接 | 自动重连 |
| SSE 重连中 | 顶部连接状态 | 显示重连中 | 等待恢复 |
| SSE 重连失败 | 顶部错误区 + 日志区 | 提示实时中断 | 允许手动刷新 |
| 继续生成失败 | 顶部错误区 | 恢复按钮可点击 | 可重试 |
| 停止生成失败 | 顶部错误区 | 恢复按钮可点击 | 可重试 |
| 重生成失败 | 章节错误区 + 日志区 | 保留旧结果 | 可再次重试 |
| 章节不存在 | 章节页主区域 | 显示不存在页态 | 返回详情页 |
| 正文流中断 | 章节页正文区 | 保留已收到片段并标记中断 | 自动重连后校准 |
| 漫画单页失败 | 章节页漫画区 + 日志区 | 不影响正文阅读 | 允许后续重试 |

### 2. 空状态

| 页面 | 场景 | 展示文案 | CTA |
|------|------|------|------|
| 首页 | 无作品 | 暂无作品，开始创建第一部小说 | 新建作品 |
| 详情页 | 无章节 | 暂无章节，等待开始生成 | 继续生成 |
| 详情页 | 无日志 | 暂无事件，开始生成后这里会显示实时过程 | 无 |
| 详情页 | 尚未开始生成 | 作品已创建，尚未进入生成流程 | 开始/继续生成 |
| 详情页 | 已停止 | 当前生成已暂停 | 继续生成 |
| 详情页 | 已全部完成 | 所有章节和漫画已完成 | 查看章节 |
| 章节页 | 计划中但未生成 | 本章尚未生成，正在等待内容 | 返回详情 / 等待本章开始 |
| 章节页 | 章节不存在 | 当前章节不存在 | 返回详情页 |
| 章节页 | 无漫画 | 本章漫画尚未生成 | 等待生成 |
| 章节页 | 漫画生成中 | 漫画正在生成中 | 保持当前页 |

## 八、前端实现建议

### 1. 组件和页面

建议新增或重构以下前端部分：

1. `HomeView.vue`：增强书架状态展示与快捷操作。
2. `NovelDetail.vue`：重做为总控页。
3. 新增 `ChapterView.vue`：承担章节阅读与实时正文展示。
4. 可复用组件：
   - `StatusCard`
   - `ChapterList`
   - `EventLogPanel`
   - `StreamTextPanel`
   - `ComicGallery`

### 2. SSE 消费抽象

建议抽出统一 composable，例如 `useNovelStream`，负责：

1. 建立和关闭 SSE 连接。
2. 将结构化事件分发给页面。
3. 维护连接状态。
4. 提供统一的错误处理与重连后校准钩子。

### 3. API 层

现有 `web/src/api/index.js` 需要扩展：

1. 章节页接口消费。
2. 统一 SSE 事件解析。
3. 支持首页快捷停止/继续。
4. 适配详情页和章节页的新数据结构。

## 九、后端实现建议

### 1. SSE 推送层

需要把当前字符串式推送改为结构化 JSON 事件推送。后端应统一定义事件结构，避免各处手写不同格式字符串。

### 2. 章节流式正文推送

章节写作阶段需要暴露稳定的流式回调，并转发为 `chapter_stream` 事件。没有这一层，章节页无法展示实时正文。

### 3. 作品级状态与汇总推送

在以下关键节点推送状态和汇总：

1. 开始生成
2. 大纲开始/完成
3. 章节开始/完成/失败
4. 漫画开始/完成/失败
5. 停止生成
6. 继续生成
7. 全部完成

## 十、验收标准

本轮完成后，至少满足以下结果：

1. 用户在作品详情页能看到当前作品的完整控制和状态信息。
2. 用户可以点击章节进入章节页查看正文。
3. 当章节正在生成时，章节页可实时看到流式正文。
4. 当用户点击“继续生成”时，详情页有即时反馈，章节页可追踪正文生成。
5. 当用户点击“重生成章节”时，章节状态、事件流和章节正文能形成完整闭环。
6. 页面具备明确空状态、错误提示、连接状态、按钮禁用和加载反馈。

## 十一、实施顺序建议

建议按以下顺序执行：

1. 重构后端 SSE 事件协议。
2. 新增章节页与章节路由。
3. 重做作品详情页。
4. 增强首页状态与快捷操作。
5. 做联调与交互收尾。

## 十二、总结

本设计不追求“只做最小修补”，而是围绕当前核心创作链路，把前端交互补齐为可实际使用的状态。

最终交互原则是：

1. 首页看整体。
2. 详情页做总控。
3. 章节页看正文和实时生成。
4. SSE 不再只是一行文本，而是驱动整个前端状态系统。
